4. הם מדברים דרך הרשת, באמצעות בקשות HTTP. למשל stats שולח בקשה ל-backend ומקבל ממנו את רשימת המוצרים.
5. ג
6. כי stats לא ניגש למסד הנתונים. הוא מבקש את המוצרים מה-backend, ורק ה-backend מדבר עם postgres.
7. יותר מורכב לנהל: יש הרבה סרוויסים שצריך להפעיל ולחבר, והתקשורת ביניהם דרך הרשת יכולה להיכשל.
8. image הוא החבילה המוכנה, כמו מתכון או עוגה קפואה, והוא לא רץ. container הוא image שרץ עכשיו. מ-image אחד אפשר להריץ הרבה containers.

10. ב
11. 8080 הוא הפורט במחשב שלי. אני נכנסת אליו בדפדפן, והוא מועבר לפורט 80 בתוך ה-container.
12. ב
13. בשביל ה-cache. הקוד משתנה הרבה וה-requirements כמעט לא. אם מתקינים את התלויות קודם, הן נשארות ב-cache והבנייה מהירה כשמשנים רק את הקוד.
14. בתוך container, localhost הוא רק ה-container עצמו, ואי אפשר להגיע אליו מבחוץ. 0.0.0.0 מאזין לכל הכתובות, ולכן החיבור דרך -p עובד.
15. מסיבות אבטחה: סיסמה בקוד נחשפת לכל מי שרואה את הקוד או את הריפו. במשתנה סביבה אפשר לשנות אותה בלי לשנות את הקוד.
16. stats עצמו עובד (/health מחזיר 200). אבל /stats מבקש נתונים מה-backend, וה-backend לא רץ, ולכן מקבלים 502.
17. docker stop עוצר container שרץ, אבל הוא ממשיך להתקיים. docker rm מוחק את ה-container.
18. Docker הוריד את הגרסה latest. היא משתנה עם הזמן, ולכן אי אפשר לדעת איזו גרסה תרוץ. בסרוויס אמיתי צריך גרסה מדויקת כדי שהתוצאה תהיה אותה תוצאה תמיד.
